# 2026-09-24 — M7 rollback: bank-1 rodata pragma broke all text

## Symptom

After the "Milestone 7 complete" commit (6f1d999), every screen in the
emulator rendered garbled text (wrong characters in the correct tiles/
layout). The build script also stopped completing: the linker printed
`Warning: Segment 'FAR_DATA' does not exist` and, because
`build.ps1` runs with `$ErrorActionPreference = "Stop"`, the native
stderr line from cl65/ld65 became a terminating error. The script died
right after linking, leaving a 64 KB unpadded, unchecksummed ROM in
`build/`.

## Root cause (two independent bugs in 6f1d999)

### 1. `#pragma rodata-name ("FARRODATA")` in main.c — the garbled text

The M7 commit moved the self-drive script tables (`scf`/`scp`,
`scf2`/`scp2`, `scf3`/`scp3`) out of `main.c` into a new `src/far_data.s`
(segment `FARRODATA`, LoROM bank 1 at CPU `$018C00+`) and added this line
at `src/main.c:256`, *above all function definitions*:

```c
#pragma rodata-name ("FARRODATA")
```

`#pragma rodata-name` is file-scope: it changes where cc65 puts the
rodata of **everything that follows in the file** — including **all C
string literals**. Since nearly every `draw_*`/`tick_*` function comes
after that line, the map file for the broken build shows:

```
RODATA                 00E886  00E966  0000E1   (225 bytes: only the
                                                const arrays defined
                                                before the pragma)
FARRODATA              018C00  01A37F  001780   (all game strings, bank 1)
```

C code references string literals with **16-bit absolute addresses**.
ld65 silently truncated the 32-bit bank-1 addresses (`$018C00+`) to 16
bits (`$8C00+`), which points into bank-0 CODE/RODATA. Every
`draw_text()` therefore read binary code/tables as characters →
garbled text with correct tiles, layout and colors.

The bug passed the `tests/host` harness because the host image maps
`FARRODATA` into contiguous test ROM/RAM where the low 16 bits *are* the
real addresses — the bank collision only exists on real LoROM hardware.

### 2. Unused `FAR_DATA` segment in snes-lorom.cfg — the broken build

The same commit added two segments to `scripts/snes-lorom.cfg`:

```
FARRODATA: load = BANK1, type = ro;   ; used by far_data.s
FAR_DATA:  load = BANK1, type = ro;   ; used by NOTHING
```

ld65 warns about the unused one, and under `EAP=Stop` the warning's
stderr line kills `build.ps1` before padding + checksum + validation.
Any future ld65/ca65 warning will now abort the build the same way —
the script must tolerate native warnings (see build fix below).

## Fix (rollback)

- `src/main.c` and `scripts/snes-lorom.cfg` restored to b9eef19 (M6)
- `src/far_data.s` deleted
- in-progress `tests/host` changes that referenced `far_data.s` reverted
- README / AGENTS.md / MILESTONES.md updated to reflect the rollback

Verified: rebuilt from the M6 tree, `build.ps1` green (256 KB, header
score 20), Mesen-S attract-mode capture matches
`docs/screens/attract.png` exactly (sector 1 demo, all text legible).

## Bank-0 headroom for the M7 rework (measured on the M6 build)

```
STARTUP  008000  008041   (0x0041)
CODE     008041  00DD88   (0x5D48)
RODATA   00DD89  00F2D7   (0x154F)
ROM area ends at 0xFFBF -> ~3.3 KB free in bank 0
```

M6's self-drive tables (`scf`/`scp`/`scf2`/`scp2`/`scf3`/`scp3`, ~1.1 KB)
plus all game strings fit in bank 0, and the M7 combat strings add only
~1 KB — so the rework should keep **all C const data in bank 0 RODATA**.
No bank-1 const data needed; no `#pragma rodata-name`, ever.

## Rules learned

1. NEVER `#pragma rodata-name` in main.c. C strings are referenced with
   16-bit addresses; only bank 0 is reachable that way.
2. Bank-1 const data (like the M6 font) must be accessed with explicit
   far/banked loads in asm or C, never as plain 16-bit C arrays.
3. The host harness cannot catch bank-mapping bugs — emulator
   screenshots remain the display ground truth (as always in this repo).
4. `build.ps1` must not die on native warnings: keep
   `EAP=Stop` for cmdlets but swallow native stderr for toolchain
   invocations (or check `$LASTEXITCODE` only).

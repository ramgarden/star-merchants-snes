## Root cause 1: cross-bank JSR (the black screens)

Symptom: every tour ROM blacked shortly after warping (both emulators,
13+ runs), while pristine-M7 and static micro-builds stayed green.

Bisected (temp builds, all since removed): gen-hook call vs content,
fight vs sector, single-stepped down to `gfersec = guniv>>1` blacking
while `gfersec = 3u` greened. The difference: `>>1` on `uint16`
emits a `jsr shrax1` to a none.lib helper that lives in **bank 0**
— but the caller runs in **bank 1**, and 65816 `jsr` uses PBR, so it
landed in bank-1 zeros (`$01E9xx` = BRK-sled): wander, garbage reads,
occasional hangs. Host never catches it (flat 6502 address space, no
banks); M7 never calls bank-1 code at all.

Fix: bank-1 C is now **helper-free** — all `<<`/`>>` on `uint16`
rewritten as shift-add doubling chains (`gom += gom`), `gfar_o++`
verified inline, rank extraction as bounded subtract loops. New build
gate in `tools/verify_far.py` compiles `m8.c` and fails on any call
that isn't an `m8*` function or `farbyt1`. Also added the bank-1 twin
`farbyt1` (same reason: bank-1 must never `jsr` the bank-0 `farbyt`).

New hard rule: **no bank-1 → bank-0 calls, ever** (data via BSS
globals is fine — absolute addressing is bank-agnostic with DBR=0).

## Root cause 2: X-discipline (XP 64291)

Symptom: Ferrengi victory showed XP 64291 (0xFF28) instead of 40.

`m8alien` does `gtmp = farbyt1()` (`uint16 = uint8`), which cc65
compiles to `STA lo + STX hi`, trusting X=0. But asm leafs left X
holding the far offset low byte ($FB). Fix: `LDX #0` before `RTS` in
both farbyt leafs. New hard rule: **asm leafs return X=0** (host
6502 codegen masks this — hardware-only bug class).
